## Section 4 — Automatic retention

- Added one `RetentionService` for post-run, startup/daily housekeeping, and the existing manual IPC route. Its single repository predicate uses one captured UTC instant and a parameterized date-added cutoff; zero days keeps records forever. Tracked states, favorites, notes, removed jobs, and suppression records remain protected. Retention continues while automatic scraping is paused and includes disabled workflows.
- Housekeeping attempts a non-cancelling exclusive write permit. If a scrape or maintenance operation owns the write window, it retries after one minute; otherwise it runs immediately after app startup and every 24 elapsed hours. The service persists the last attempt/success, deleted count, consecutive failure count and error, publishes an update event, and the Data management view reports the result and provides a repeated-failure action hint. Deletion refreshes jobs, totals, pagination, metrics, workflows and selection via the shared cache path. Rust-generated `RetentionStatus` is used by the frontend.
- Added fixed-clock repository coverage for the exact expiry boundary, recent rescrapes, and protected records; service coverage for paused/disabled sources, zero-day retention and failure/reset status; runner coverage that a busy scrape is not cancelled; and UI/event coverage for the persisted status and cache refresh. The isolated native smoke now checks startup cleanup while paused and all workflows are disabled. Its existing font acceptance now selects through the themed Listbox exposed by the app.
